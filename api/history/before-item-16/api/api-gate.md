# API-GATE: огляд контракту після ADD-001

Дата: 29 жовтня 2026 року. Огляд підготував Codex. **Статус: технічний огляд завершено; рішення людини очікується. Gate не оголошено PASS або GO.**

Обсяг: документи REST API, OpenAPI 3.1.0 і докази статичного відтворення mock. Основа критеріїв — поточне завдання API-GATE та погоджені завдання API; окремого нормативного чекліста API-GATE чи повного тексту лабораторної в репозиторії не знайдено. Джерела вимог: [SRS](../spec/srs.md), [функціональні вимоги](../spec/functional-requirements.md), [ADD-001](../spec/srs-addendum-001.md), [AC](../spec/acceptance-criteria.md), [BDD](../spec/bdd-scenarios.md), [глосарій](../spec/glossary.md).

Порядок прийняття: [roles.md, Gate / CP-08](../planning/roles.md) залишає рішення за людиною: «Агент не ухвалює Validation і Gate від імені студента». [CP-08](../planning/revised-decomposition.md) вимагає автора, дати, версії, обґрунтування й обсягу рішення. Цей огляд збирає докази для такого рішення, не замінює G-SPEC/G-PLAN/G-READY/G-ACCEPT і не дозволяє backend.

«Відповідає» нижче означає результат огляду зазначеного артефакту; «PASS» у рядках прогонів — лише результат відповідного інструмента. Це не автоматичне прийняття Gate.

## Залишкові зауваження та вплив на Gate

| Зауваження / обмеження | Вплив на цей огляд |
| --- | --- |
| Невикористані schemas/CatalogQuery та schemas/AvailabilityQuery | Неблокувальні попередження: агреговані схеми документують пари меж; операції використовують окремі query-параметри, міжпараметрові залежності перевіряє сервер. Попередження не вимкнено |
| Невикористані responses/MethodNotAllowed і headers/Allow | Неблокувальні попередження: у маршрутах застосовані спеціалізовані 405 з власними Allow. Базовий шаблон не робить контракт невалідним; можна прибрати окремою технічною зміною |
| Власні application/problem+json Prism, транспортні відповіді proxy, нормалізація JSON Schema у Prism | Обмеження інструментів. Перевірені погоджені named examples оцінюються незалежним OAS31Validator; не засвідчено повну підтримку всіх можливих значень JSON Schema 2020-12 або відповідність власних помилок Prism моделі API |
| Невизначені загальний пріоритет незалежних порушень і точні тексти/field усіх міжпольових помилок | Не блокують погоджені незалежні сценарії та стабільні коди. Нових правил не введено; ці випадки не вважаються перевіреними |

| Глобальна spec/traceability-matrix.md ще не містить ADD-001 | Оновлюється в **пункті 16**, як визначено завданням. ## Висновок і рішення

**Блокувальних недоліків у перевіреному контракті та доказах статичного mock не виявлено.** Пакет готовий до людського розгляду API-GATE з наведеними зауваженнями. Це висновок технічного огляду, а не автоматичний PASS, прийняття реалізації чи дозвіл на перехід.

| Версія й обсяг | Наведений SHA-256 OpenAPI та маніфест доказів; документи контракту й статичні mock-відповіді після ADD-001 |
| Рекомендація огляду | Розглянути прийняття контракту в цьому обсязі з неблокувальними зауваженнями; глобальну матрицю доповнити в пункті 16 |
| Межі рішення | Не є GO на backend, повним G-ACCEPT або підтвердженням бізнес-тестування |
