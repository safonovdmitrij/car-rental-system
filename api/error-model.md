# Єдина модель помилок REST API

Модель застосовується до вже визначених [операцій](operations.md) з префіксом `/api/v1`. Статуси узгоджено з [контрактом запитів і відповідей](requests-responses.md), тип Quote — зі [схемами даних](data-schemas.md). Машинні назви кодів і форма помилок є проєктними рішеннями; маршрути й бізнес-правила не змінюються.

## Структура

Схема ErrorResponse: відповідь має Content-Type: application/json і є об’єктом з одним полем error. Усі три поля всередині error обов’язкові; null замість об’єктів або рядків не допускається.

| Поле | Тип | Обов’язковість | Обмеження / опис |
| --- | --- | --- | --- |
| error | object | Так | Містить code, message, details |
| error.code | string | Так | Стабільний машинний код із таблиць нижче; клієнт обробляє помилку за ним і HTTP-статусом |
| error.message | string | Так | Непорожнє пояснення українською; для 404 текст фіксований, для решти клієнт не покладається на точне формулювання |
| error.details | object | Так | Типово {}; для валідації містить fields, для PRICE_CHANGED — quote |
| error.details.fields | array<FieldError> | Для VALIDATION_ERROR | Щонайменше один елемент; не містить введених значень |
| FieldError.field | string | Так у кожному елементі | Ім’я поля контракту, наприклад startsAt, currentPassword; для вкладених даних шлях characteristics.<назва>. Для помилки всього тіла (наприклад порожній PATCH) — $ |
| FieldError.message | string | Так у кожному елементі | Пояснення українською з непробільним символом, без копіювання значення поля |
| error.details.quote | Quote | Для PRICE_CHANGED | Повний оновлений розрахунок за наявною схемою, включно з новим priceConfirmationToken |

Для решти кодів details = {}. FieldError — вкладена схема елемента fields, а не додаткове поле відповіді. У field використовується лише безпечна назва/шлях поля: довільні передані ключі, які можуть містити приватний текст, не відображаються; можна вказати батьківське characteristics або $.

## Загальні помилки та доступ

Позначення OP відповідають [таблиці операцій](operations.md). Захищені операції — OP-06–OP-22; OP-01–OP-05 не вимагають чинної Bearer-сесії. Коди нижче доповнюють HTTP-статуси, наведені біля операцій, без введення нових перевірок.

| HTTP | error.code | Операції | Умова виникнення |
| --- | --- | --- | --- |
| 400 | BAD_REQUEST | Операції з JSON, параметрами шляху або query | JSON неможливо розібрати або синтаксис URI/query пошкоджено; коректний синтаксис із недопустимими даними — 422 |
| 401 | AUTHENTICATION_REQUIRED | Захищені операції | Bearer-автентифікація відсутня або недійсна; details не пояснює внутрішню причину відмови |
| 403 | FORBIDDEN | Захищені операції | Чинна сесія має недозволену роль; зокрема А виконує OP-10 або К — адміністративну операцію |
| 404 | NOT_FOUND | OP-02, OP-03, OP-09, OP-10, OP-12, OP-13, OP-16–OP-22 | Немає запитаного ресурсу; periodId не належить carId; також приховане авто в OP-02 для Г/К або чуже бронювання для К |
| 404 | NOT_FOUND | Невідомий маршрут | Такого URI немає |
| 405 | METHOD_NOT_ALLOWED | Відомі URI з непідтримуваним методом | Метод не визначений для цього URI; Allow містить підтримувані методи |
| 500 | INTERNAL_ERROR | Усі | Непередбачена внутрішня помилка; загальне повідомлення без технічних подробиць |
| 503 | SERVICE_UNAVAILABLE | Усі | Тимчасова недоступність сервісу; загальне повідомлення без технічних подробиць |

На захищених операціях автентифікація та перевірка ролі передують перевірці існування ресурсу. Власність бронювання перевіряється без розкриття його існування: для чужого й відсутнього бронювання в OP-12 та OP-13 повертається однакова відповідь `404` з code=NOT_FOUND, message="Ресурс не знайдено.", details={}. Цей самий текст і details застосовуються до інших NOT_FOUND; у тілі немає ідентифікаторів або ознак власника. Публічні читання не вимагають сесії.

## Реєстрація, вхід і валідація

| HTTP | error.code | Операції | Умова виникнення |
| --- | --- | --- | --- |
| 409 | EMAIL_ALREADY_EXISTS | OP-04 | Нормалізована пошта вже належить обліковому запису; без даних цього запису |
| 401 | INVALID_CREDENTIALS | OP-05 | Невірна пошта або пароль; спільне повідомлення без уточнення, чи існує адреса |
| 429 | LOGIN_BLOCKED | OP-05 | П’ята послідовна невдала спроба або спроба під час чинного 15-хвилинного блокування |
| 422 | VALIDATION_ERROR | OP-01, OP-03–OP-05, OP-07–OP-10, OP-13, OP-15, OP-16, OP-20, OP-21 | Відсутні, невідомі або недопустимі поля; порожній PATCH; порушення схем або вже погоджених часових правил; містить details.fields |

До VALIDATION_ERROR також належать неправильний currentPassword в OP-08, відсутня/пробільна причина адміністративного скасування в OP-13 та невалідний priceConfirmationToken або його невідповідність клієнту, авто чи періоду в OP-10. Опис поля не розкриває його значення чи внутрішню перевірку токена. Порушення порядку меж, неіснуюча дата та неіснуючий/неоднозначний час — 422 незалежно від того, чи виявила їх схема або додаткова серверна перевірка. Обмеження майбутнього початку, 1–30 діб і 90 днів застосовуються лише там, де це вже визначено контрактом.

## Бронювання та службові конфлікти

| HTTP | error.code | Операції | Умова виникнення |
| --- | --- | --- | --- |
| 409 | CAR_UNAVAILABLE | OP-09, OP-10 | Авто приховане або недоступне на весь вибраний період; зокрема втратило доступність до атомарного створення |
| 409 | PRICE_CHANGED | OP-10 | Тариф змінився після показу ціни; бронювання не створено; details.quote містить нову ціну й токен для повторного підтвердження |
| 409 | ALREADY_CANCELLED | OP-13 | Бронювання вже скасоване; новий запис скасування не виникає |
| 409 | CANCELLATION_DEADLINE_PASSED | OP-13, К | Підтверджене бронювання вже минуло клієнтську межу скасування |
| 409 | BOOKING_NOT_CANCELLABLE | OP-13, К або А | Бронювання активне чи завершене; початок оренди вже настав |
| 409 | CAR_HAS_RELATED_RECORDS | OP-17 | Є хоча б одне бронювання або службовий період, включно з історичними записами |
| 409 | SERVICE_PERIOD_CONFLICT | OP-20, OP-21 | Службовий період перетинається з підтвердженим/активним бронюванням або іншим службовим періодом; без переліку конфліктних записів |
| 409 | SERVICE_PERIOD_ALREADY_STARTED | OP-21, OP-22 | Чинний службовий період уже почався; редагування/видалення заборонено |

OP-03 повертає 200 з available=false, а OP-01 — відфільтрований список: звичайна відсутність доступності в цих операціях не є помилкою CAR_UNAVAILABLE. Для підтвердженого бронювання після клієнтської межі застосовується CANCELLATION_DEADLINE_PASSED; для активного/завершеного — BOOKING_NOT_CANCELLABLE. Інші поєднання незалежних помилок не встановлюють нового пріоритету бізнес-перевірок.

## Заголовки

| Відповідь | Заголовок | Правило |
| --- | --- | --- |
| Усі помилки | Content-Type: application/json | Тіло за єдиною структурою |
| 429 LOGIN_BLOCKED | Retry-After: <секунди> | Додатне ціле число секунд до завершення початкового блокування; залишок округлюється вгору до цілої секунди. П’ята помилка запускає 15 хвилин, повторні спроби не пересувають межу |
| 405 METHOD_NOT_ALLOWED | Allow: <методи> | Підтримувані для URI методи з наявного контракту, через кому; наприклад для /api/v1/cars — GET, POST |
| 401 AUTHENTICATION_REQUIRED | WWW-Authenticate: Bearer | Для помилок Bearer-автентифікації захищених операцій; без токенів чи внутрішніх описів |

401 INVALID_CREDENTIALS від OP-05 — помилка входу за поштою й паролем, а не Bearer-автентифікації; заголовок WWW-Authenticate: Bearer для неї не додається. Для 403 чинної сесії цей заголовок також не вимагається. Відкриті питання строку сесії й наслідків зміни пароля цією моделлю не розв’язуються.

## Приклади JSON

### Валідація — 422 VALIDATION_ERROR

Приклад для OP-07: передане ім’я складається лише з пробільних символів. Введене значення не повторюється.

```json
{
  "error": {
    "code": "VALIDATION_ERROR",
    "message": "Перевірте поля запиту.",
    "details": {
      "fields": [
        {
          "field": "firstName",
          "message": "Ім’я має містити щонайменше один непробільний символ."
        }
      ]
    }
  }
}
```

### Недоступне авто — 409 CAR_UNAVAILABLE

Приклад для OP-10; жодних даних про причину блокування періоду.

```json
{
  "error": {
    "code": "CAR_UNAVAILABLE",
    "message": "Автомобіль недоступний на вибраний період.",
    "details": {}
  }
}
```

### Зміна ціни — 409 PRICE_CHANGED

Приклад для OP-10 із допустимим на момент запиту періодом. Рядки ідентифікатора й токена — демонстраційні непрозорі значення; токен підтверджує ціну, не є токеном сесії.

```json
{
  "error": {
    "code": "PRICE_CHANGED",
    "message": "Вартість змінилася. Підтвердьте оновлену суму.",
    "details": {
      "quote": {
        "carId": "car-example",
        "startsAt": "2026-11-12T09",
        "endsAt": "2026-11-14T09",
        "timezone": "Europe/Kyiv",
        "dailyRate": "1500.00",
        "billableDays": 2,
        "totalPrice": "3000.00",
        "currency": "UAH",
        "priceConfirmationToken": "updated-price-confirmation-example"
      }
    }
  }
}
```

## Приватність

Заборонено повертати паролі, їх хеші, токени сесій, заголовок Authorization, чужі контакти, службові причини, відомості про конкретного адміністратора або внутрішні технічні деталі (стек викликів, SQL, назви таблиць, шляхи файлів, текст винятків). Правило діє для code, message, details і заголовків незалежно від ролі одержувача.

Для PRICE_CHANGED дозволено лише новий priceConfirmationToken у Quote для цього клієнта, авто й періоду; accessToken ніколи не входить до помилки. Валідація не копіює введені значення й довільні ключі, зокрема в текст пояснення. Помилки недоступності та службових конфліктів не повідомляють, яке бронювання чи службова причина спричинили відмову. Для NOT_FOUND відповідь не відрізняє чуже бронювання від відсутнього.
