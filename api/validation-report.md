# Результат автоматичної валідації OpenAPI

Дата: 29 жовтня 2026 року. Перевірено [openapi.yaml](openapi.yaml), OpenAPI 3.1.0, у Windows PowerShell, Python 3.14.0. SHA-256 перевіреного файла: `0A7C912B06EE51067C5BBD56A16EA90379F2CCE1352ED94DAE16BBA37B1A2F99`.

## Інструменти та відтворення

- **openapi-spec-validator 0.9.0**, явно вибрана схема 3.1 — перевірка документа OpenAPI. [Документація інструмента](https://openapi-spec-validator.readthedocs.io/en/latest/).
- **openapi-schema-validator 0.9.0**, клас OAS31Validator, з увімкненим FORMAT_CHECKER — перевірка прикладів за схемами, включно з oneOf/anyOf, if/then/else та внутрішніми посиланнями. [Документація перевірки схем](https://openapi-schema-validator.readthedocs.io/en/latest/validation.html).
- **jsonschema 4.26.0**, **PyYAML 6.0.3**; усі встановлені версії, включно із залежностями перевірок форматів, зафіксовано у [validation-requirements.txt](validation-requirements.txt).

Точні команди від кореня репозиторію; активація середовища не потрібна:

```powershell
python -m venv .venv-api-validation
.\.venv-api-validation\Scripts\python.exe -m pip install --disable-pip-version-check -r api/validation-requirements.txt
.\.venv-api-validation\Scripts\python.exe -m openapi_spec_validator --version
.\.venv-api-validation\Scripts\python.exe -m openapi_spec_validator --schema 3.1 --validation-errors all --subschema-errors all api/openapi.yaml
.\.venv-api-validation\Scripts\python.exe -W default api/validate_openapi.py
```

Для початкового встановлення потрібен доступ до індексу пакетів; самі перевірки працюють локально. Середовище `.venv-api-validation/` виключене через `.gitignore`. [validate_openapi.py](validate_openapi.py) використовує готові валідатори; додатковий код обходить приклади та перевіряє погоджений набір операцій, посилання й security. Код завершення 1 означає помилку; переглядові попередження залишаються видимими й не змінюють успішний код завершення.

## Результат

Обидві команди валідації завершилися з кодом **0**. CLI: `api/openapi.yaml: OK`. Допоміжна перевірка: `RESULT: PASS; errors=0; warnings=4`.

| Перевірка | Результат |
| --- | --- |
| Структура OpenAPI 3.1 | 0 помилок готового валідатора |
| YAML | Прочитано; дубльованих ключів немає |
| Внутрішні $ref | Усі 460 входжень розв’язуються |
| Операції та operationId | Рівно OP-01–OP-22, без пропусків/повторів; 22 унікальні непорожні operationId; методи й URI збігаються з operations.md |
| Базовий URI | /api/v1 у servers; у paths не повторюється |
| Схеми | 56 компонентів; приклади перевірено готовим OAS31Validator, а не лише синтаксичним парсером |
| Приклади | Усі 54 унікальні components/examples мають перевірене використання зі схемою; 314 перевірок з урахуванням повторного використання |
| Розподіл прикладів | 12 запитів, 241 відповідь, 25 параметрів, 33 заголовки, 3 приклади у схемах; враховано також повторно використовувані компоненти |
| Публічний доступ | OP-01–OP-05 допускають відсутність автентифікації; OP-01/OP-02 також дозволяють необов’язкову Bearer-сесію |
| Захищений доступ | OP-06–OP-22 вимагають HTTP Bearer; немає анонімної альтернативи |

Перевірки прикладів використовують перевірку форматів, закритість об’єктів, обов’язковість полів, регулярні вирази й умовні схеми скасування. Це перевірки статичних прикладів проти контракту; фактичні HTTP-запити не надсилалися.

## Виправлення та попередження

Технічних помилок у специфікації не виявлено, тому `openapi.yaml` не змінено. Після фіксації версій залежностей обидві команди перевірки повторено з тим самим результатом.

Готові валідатори не видали попереджень; наведені нижче **4 переглядові попередження** сформовано додатковою перевіркою досяжності компонентів від операцій. Вони не приховані й не вимкнені.

| Компонент | Розгляд / залишкове зауваження |
| --- | --- |
| schemas/CatalogQuery | Документує спільну пару query-меж і dependentRequired. Операція використовує окремі Parameter Objects; залежність параметрів перевіряє сервер. Схема збережена як опис агрегованого запиту, але прямо не підключена через $ref |
| schemas/AvailabilityQuery | Агрегований опис двох обов’язкових меж; операція посилається на окремі параметри. Компонент збережено для відповідності data-schemas.md, прямого використання немає |
| responses/MethodNotAllowed | Загальний шаблон 405. Операції використовують спеціалізовані відповіді MethodNotAllowed… з прикладами Allow для своїх URI; базовий шаблон зайвий для поточних операцій, але не робить документ невалідним |
| headers/Allow | На нього посилається лише загальний невикористаний шаблон 405; спеціалізовані відповіді мають власні Header Objects. Не досяжний від операцій; можливе подальше прибирання шаблону без зміни контракту |

## Межі висновку

Валідація підтверджує структурну коректність документа, відповідність наявних прикладів схемам і заявлені налаштування security. Вона **не підтверджує виконання бізнес-правил, фактичний захист даних або проходження API-GATE**. Роль, власність, календарна коректність, DST, поточний час, доступність, ціна та конкурентність потребують окремих перевірок реалізації.

Строк сесій, наслідки зміни пароля для сесій і календарне питання Q-07 залишаються відкритими. Mock і серверну реалізацію не запускали; бізнес-правила й вихідні вимоги не змінено. Коміту та push немає.
