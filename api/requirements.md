# Покриття функціональних вимог REST API

Погоджені уточнення: [ADD-001](../spec/srs-addendum-001.md), REQ-F-093–REQ-F-096 та додаткові AC календарних вимог. Сесія чинна рівно 86 400 секунд від входу, без автоматичного продовження. Від точної межі або після успішної зміни пароля старий токен дає 401 AUTHENTICATION_REQUIRED з WWW-Authenticate: Bearer. Успішна зміна пароля повертає 204 без тіла й анулює всі сесії цього запису, включно з поточною; наступний захищений запит вимагає повторного входу. Невдала зміна не анулює сесій, якщо їх початковий строк ще не завершився. За ADD-001 кожну обчислену календарну межу визначають від початкової місцевої опори Europe/Kyiv: неіснуючу переносять вперед на величину переходу, для неоднозначної вибирають пізніший момент. Перенесення не накопичуються. Це діє для меж 1/30 діб, оплачуваних діб та горизонту 90 днів; введені проблемні години як і раніше відхиляються з 422, правило дедлайну скасування збережено.


Джерела: [SRS](../spec/srs.md), [вимоги](../spec/functional-requirements.md), [глосарій](../spec/glossary.md), [критерії](../spec/acceptance-criteria.md), [BDD](../spec/bdd-scenarios.md). Стислі формулювання нижче не замінюють джерела. Покрито всі 96 REQ-F; автоматичні правила виконує сервер, окремих операцій для них немає.

Маршрути, назви полів, HTTP-коди та форми представлень є **проєктними**. Усі URI мають префікс `/api/v1`; у таблицях цього файла він опущений. Деталі: [ресурси](resources.md), [операції](operations.md), [запити й відповіді](requests-responses.md).

Точні зв’язки OP → REQ та їх обґрунтування наведено в [трасованості API](traceability.md). Колонка операцій нижче задає зворотні зв’язки через OP-ID з operations.md: якщо вимоги в одному рядку мають різні набори операцій, набір зазначено окремо для кожної вимоги. Це опис контракту, а не підтвердження реалізації чи проходження тестів; відсутність PATCH бронювання є також структурною гарантією REQ-F-045.

Типи та обов’язковість полів: [схеми даних](data-schemas.md). Погоджені проєктні уточнення до REQ-F-002, REQ-F-037, REQ-F-065–REQ-F-067, REQ-F-073–REQ-F-075: characteristics — непорожній словник непорожніх рядків; dailyRate > 0 з двома десятковими знаками; службові межі також задаються як YYYY-MM-DDTHH у Europe/Kyiv з відхиленням неіснуючого й неоднозначного часу. Обмеження 1–30 діб і 90 днів на службові періоди не переносяться. Уточнення не змінюють вихідних REQ-ID; їх зв’язки з AC наведено в схемах.

## Каталог і доступність

Уточнення схем: NonEmptyString для імен, телефону, причин, назв і значень характеристик вимагає непробільного символу, без зміни чи обрізання паролів. Для LocalHour схема перевіряє структуру й діапазони компонентів; існування календарної дати та коректність часу в Europe/Kyiv додатково перевіряє сервер.

| REQ-F-001, REQ-F-002 | Операція | Публічний каталог із характеристиками й тарифом | OP-01, OP-02 |
| REQ-F-003 | Бізнес-правило | Без періоду — всі неприховані авто, без оцінки доступності | OP-01 |

| REQ-F-006 | Операція | Перевірка конкретного авто | OP-03 |

Пошук і перевірка доступності перевіряють коректність дат, порядок меж, цілі години й неоднозначний/неіснуючий час у Europe/Kyiv. Обмеження майбутнього початку, тривалості 1–30 діб і горизонту 90 днів застосовуються лише до розрахунку вартості й створення бронювання.
