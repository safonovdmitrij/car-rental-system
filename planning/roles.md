# Ролі в SDD-циклі

Чинні джерела: [декомпозиція](revised-decomposition.md), [залежності](ticket-dependencies.md), [Issues](issue-mapping.md), [етапи](phased-plan.md). Один студент, максимум 4 год/тиждень, і один агент. Міграція не є GO; усі рішення очікують людини.

| Тип / картка | Агент | Людина | Хто приймає |
| --- | --- | --- | --- |
| Specification / CP-01 #1 | Аналізує SRS, неоднозначності й варіанти | Спільно уточнює трактування, відповідає на Q | Людина |
| Addendum / CP-02 #2 | Готує доповнення перевірок лише чинних REQ | Спільно перевіряє й погоджує очікування | Людина |
| Test / CP-03 #7 | Переважно готує випадки, очікування, фікстури й методику запуску | Перевіряє повноту й готовність для погодженого обсягу | Людина; готовність враховується в G-READY |
| Feature / CP-04 #13 | Переважно проєктує, реалізує дозволений обсяг і локально перевіряє | Перевіряє проєктування й передані зміни | Людина з урахуванням CP-05 |
| Verification / CP-05 #29 | Спільно виконує прогони після коду, відтворює дефекти, збирає докази | Перевіряє покриття й достатність доказів відповідності | Людина приймає звіт |
| Validation / CP-06 #35 | Лише готує допоміжні питання, зіставлення й демонстрацію | **Виконує виключно людина:** Validation задуму та результату | Лише людина |
| Documentation / CP-07 #37 | Переважно готує план, простежуваність, інструкції й докази | Перевіряє точність, повноту й зрозумілість | Людина |
| Gate / CP-08 #3 | Збирає посилання на матеріали інших карток; Gate не створює код, тести, дані або проєктування | **Лише людина** вирішує G-SPEC, G-PLAN, G-READY, G-ACCEPT; фіксує автора, дату, версію, обґрунтування й обсяг | Лише людина |

Агент починає Feature лише після актуального явного GO людини у G-READY, готовності відповідних Test, погоджених очікувань і технічних B. Один G-READY дозволяє погоджений обсяг, без 16 персональних рішень. Виключені REQ блоковані до перегляду того самого G-READY. Зміна обсягу/очікувань потребує його перегляду.

Test-ready до коду — підготовка тестів; Test-pass після коду — результат у Verification. Закриття Issue, чекбокс або мовчання не є GO. Агент не ухвалює Validation і Gate від імені студента.

Без подвійного обліку: Feature — огляд змін та проєктування; Verification — огляд звіту фактичних прогонів REQ/AC/BDD і інтеграції; Validation — придатність для задуму; Gate — рішення про перехід за вже перевіреними матеріалами, без повторного повного огляду коду. Готові незалежні матеріали й окремі основні рішення можна розглянути в одній двогодинній сесії. Агент між сесіями продовжує незалежну дозволену роботу.
